# roavilo 全站三端页面样式与交互验收规范

更新日期：2026-09-06

## 0. 对标目标与版权边界（先读）

roavilo 的验收目标：**在功能、信息架构、URL path 结构、交互模式和响应式行为上对标 dianping.com 同类页面；页面可见品牌为 roavilo。**

必须明确的边界：dianping 的页面视觉设计、图标、素材、文案受版权保护，roavilo 不做像素级 1:1 复刻，视觉采用 roavilo 原创设计（橙色主题、自有卡片/栅格体系）。因此"隐藏 Logo 后无法分辨哪个是 dianping"不作为验收标准；验收标准是：**相同 URL 结构下，页面的模块构成、信息层级、交互可用性、三端响应式行为达到同类平台可用水平，且登录/非登录状态差异完整**。任何要求照抄 dianping 像素、颜色、素材的指令都受此边界约束。

## 1. 三端断点矩阵

| 端 | 断点 | 必须验证的行为 |
| --- | --- | --- |
| PC | >1024px | 顶栏完整（logo/城市切换/主导航/搜索/用户区）、4 列商户网格、商户详情双栏 |
| iPad | 769–1024px | 3 列网格、搜索框收窄、详情页单栏 |
| 手机 | ≤768px | 底部 Tab 栏（首页/商户/团购/我的）、2 列网格、主导航隐藏、用户菜单仅显示头像 |
| 小屏手机 | ≤480px | 单列网格 |

所有页面在 1440px、820px、390px 三档下不得出现横向溢出；底部 Tab 栏需兼容 iOS 安全区（`env(safe-area-inset-bottom)`）。

## 2. 登录/非登录状态差异（每页必查）

| 位置 | 非登录态 | 登录态 |
| --- | --- | --- |
| 顶栏右侧 | 「登录 / 注册」按钮 | 头像+昵称，下拉菜单含：我的主页/我的点评/我的收藏/我的订单/个人资料/商户中心/（管理员可见：管理后台）/退出登录 |
| 顶部提示条 | 引导登录条 + 立即登录/免费注册按钮 | 欢迎条（昵称问候 + 快捷入口） |
| 手机底部 Tab 第 4 格 | 🔑 登录 | 👤 我的 |
| 商户详情页 | 不显示写点评表单、收藏按钮；点赞显示为纯计数 | 完整点评/收藏/点赞/回复表单 |
| 团购详情页 | 「登录后购买」 | 数量选择 + 抢购表单 |
| 受限路由 | 302 跳登录 | 正常访问；越权操作返回 403 |

下拉菜单使用纯 CSS `focus-within`，必须验证键盘 Tab 可达与点击外部关闭（点击关闭由脚本承担）。

## 3. 必须覆盖的页面链路与状态

以下每条链路须在 1440/820/390 三档各验收一次，并覆盖正常、空数据、校验失败、越权/未登录、404 五类状态；不能只看页面 200。

1. **城市首页** `/`→`/{城市}`：分类导航、热门商户、热门团购、最新点评、热门城市切换；未知城市 slug 必须 404（不得 500）。
2. **城市选择页** `/city`：热门/全部网格、点击后 session 记忆城市。
3. **分类列表** `/{城市}/ch{id}`：分类/区域/排序筛选保留 query 参数；分页 `withQueryString` 不丢筛选。
4. **搜索** `/search/keyword/{城市ID}/0_关键词`：中文关键词、空结果、URL 编码；联想接口 300ms 防抖、点击外部关闭。
5. **商户详情** `/shop/{id}`：星级分布条比例正确；rf=good/mid/bad 筛选与 r_sort=new/old/hot 排序实测生效；发布点评（10 字下限校验、一人一店一评重复提交走更新）；点赞 toggle、回复、收藏 toggle。
6. **团购闭环** `/deal/{id}` → 下单 → 模拟支付（生成 12 位核销码）→ 用户订单页可见核销码 → 商户中心核销 → 订单状态 0→1→2；核销码错误/重复核销/跨店核销必须被拒绝。
7. **个人中心** `/user` 及子页：统计数字与实际数据一致；头像文件上传（2MB、图片类型校验）与 URL 两种方式。
8. **商户中心** `/merchant/shops/{shop}/*`：看板统计、店铺编辑、点评管理（回复带【商家回复】前缀）、团购 CRUD（团购价≤原价、结束≥开始校验）、上下架切换；非店主全部 403。
9. **管理后台** `/admin/*`：店铺审核上下架、用户搜索与管理员切换、点评删除后店铺评分重算、分类/城市增删（有从属数据时拒绝删除）；普通用户 403。
10. **站点页** footer 12 链接（about/contact/help/kf/app/agreement/privacy/merchant-convention/promote/news/jobs/商户入驻）全部 200；`/kf` 反馈表单：登录用户自动带昵称邮箱、游客缺联系方式被拒绝、提交成功入库。
11. **资讯** `/news` 分类筛选、`/news/{id}` 未发布 404、相关推荐。
12. **旧 URL** 5 条 301 跳转：目标 path 与 query 保留、单跳。

## 4. 交互验收细则

- 筛选/排序 active 态、卡片 hover 上浮、按钮 disabled 态一致。
- 表单校验错误内联展示（红色提示），成功提示经 session flash 渲染。
- 回到顶部：滚动 400px 出现，平滑滚动；手机端不遮挡底部 Tab。
- 分页控件：当前页高亮，翻页保留筛选参数。
- 空状态必须给文案与引导（如"暂无点评，快来抢沙发"），不得渲染空白区块。

## 5. 数据一致性红线

- 用户订单页与商户订单页读取同一批 `deal_orders`；核销后两侧状态必须一致，不允许两套副本。
- 点评发布/删除后 `shops.rating`、`rating_count` 必须同步重算。
- 商户中心所有操作的越权校验以 `shops.owner_id` 为唯一依据。

## 6. 回归记录方式

当前无 PHPUnit 基线，每次相关变更后按《功能测试清单.md》执行 curl 回归并记录：请求 → 状态码 → 数据库状态断言。涉及下单/支付/核销/点评的变更，必须重跑完整业务闭环并断言订单状态流转，截图或 HTTP 200 不能替代数据库断言。
