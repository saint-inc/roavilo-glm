# roavilo 数据库表说明

更新日期：2026-09-06

当前权威基线：本地 MySQL（`127.0.0.1:3306`，库名 `roavilo`，root 无密码）为 **11 条迁移、22 张表**，其中业务表 14 张（含 news/feedbacks），框架表 9 张（password_reset_tokens、sessions、cache、cache_locks、jobs、job_batches、failed_jobs、migrations；users 为框架表扩展）。本轮（is_demo 改造）没有修改既有字段，仅新增 `is_demo` 列并扩充 Demo 数据。

**城市与行政区数据（2026-09-06 扩充）**：`CityRegionSeeder`（独立 seeder，由 DatabaseSeeder 调用）提供**51 个真实城市 + 392 个真实行政区**——覆盖 4 直辖市、省会及主要地级市（含三亚、拉萨、东莞等），每城下辖真实区县（如上海 16 区、北京 12 区、广州 11 区）；热门城市 16 个（控制首页热门栏与城市选择页分组），城市 slug 为全拼（与 `/{城市拼音}` URL 结构一致）。区县按城市隔离存储（多地都有"朝阳区"等重名区县，商户绑定 region 时按 city_id+name 精确匹配，Seeder 内做了区域缓存防串城）。demo 商户分布：上海 12 家 + 北京 3 家（东城/朝阳/海淀），多城市数据隔离已实测（北京美食页 2 张卡片含簋街小龙虾，上海页不含北京店，东城区筛选只出东城商户）。

**is_demo 机制（2026-09-06 起生效）**：全部 14 张业务表均有 `is_demo`（boolean，默认 false，带索引）：1=demo 数据，0=真实数据。约定：**应用代码（app/routes/resources）不读写该字段**（已 grep 验证零引用），仅迁移文件负责建列、Seeder 在收尾对本库全部记录统一置 1。上线清理口径：`DELETE FROM 表 WHERE is_demo=1`（按依赖顺序），随后执行该迁移的 `down()` 删除字段。

**Demo 状态覆盖矩阵（2026-09-06 第二版，为调试而生）**：demo 数据刻意覆盖每张表的各种记录状态——
- `shops`：营业中 10 / 待审核 1 / 已下架 1（后台审核流与前台过滤均可调）；营业时间含正常/24 小时/未设置三种
- `deals`：在售 6 / 已下架 1 / 已过期 1 / 未开始 1 / 售罄(stock=0) 1
- `deal_orders`：待支付 3（无码）/ 已支付 5（含码）/ 已使用 2（码已消费）
- `reviews`：5 星 13 / 4 星 13 / 3 星 6 / 2 星 3 / 1 星 3（好评/中评/差评筛选与星级分布条全可测，实测 shop/3 差评 2 条、中评 1 条）；cost 含已填/未填两态
- `news`：已发布 9 / 未发布 1（列表不显示、详情 404 已验证）
- `feedbacks`：待处理 8 / 已处理 2；登录提交 5 / 游客提交 5
- `users`：管理员 1 / 普通 9；有头像资料 4 / 无头像资料 6
- `categories`：一级 12 / 二级 2（本帮江浙菜→美食、美发→丽人）
- `cities`：热门 6 / 非热门 4

每表至少 10 条：users 10、cities 51、categories 14、regions 392、shops 15、shop_images 10、reviews 40、review_replies 10、review_likes 12、favorites 10、deals 10、deal_orders 10、feedbacks 10、news 10；全部记录 is_demo=1 已核验。

主业务关系为：

```text
cities 1 ── N shops N ── 1 categories / regions
users 1 ── N shops（owner_id，商户主）
users 1 ── N reviews / favorites / deal_orders
shops 1 ── N reviews / deals / shop_images / favorites
reviews 1 ── N review_replies / review_likes
deals 1 ── N deal_orders（verify_code 为核销凭证）
```

订单与核销的关键约束：`deal_orders.order_no` 与 `verify_code` 各自独立唯一；`verify_code` 仅在支付成功时生成，核销把状态从 1（已支付）改为 2（已使用）并写入 `used_at`。点评使用 `(shop_id, user_id)` 唯一索引保证一人一店一评。

## 1. 城市与类目

### 1.1 `cities`

用途：平台覆盖城市，`slug` 用于 URL `/{城市拼音}`。

| 字段 | 类型/约束 | 功能说明 |
| --- | --- | --- |
| `id` | bigint unsigned，PK | 城市主键；同时是搜索 URL `/search/keyword/{cityId}/...` 的编号。 |
| `name` | varchar(50) | 城市中文名。 |
| `slug` | varchar(50)，UK | 城市拼音，城市首页与分类页 path 的一部分。 |
| `is_hot` | boolean，默认 false | 热门城市标记，控制城市选择页与首页热门栏。 |
| `sort` | int unsigned，默认 0 | 展示排序。 |

主要关系：1:N `regions`、`shops`。管理后台删除城市时若存在商户会被拒绝。

### 1.2 `categories`

用途：商户经营类目，支持 `parent_id` 两级结构；一级分类对应 URL `/{城市}/ch{分类ID}`。

| 字段 | 类型/约束 | 功能说明 |
| --- | --- | --- |
| `id` | bigint unsigned，PK | 分类主键；URL `ch{id}` 使用该值。 |
| `name` | varchar(50) | 分类名（应用层唯一校验）。 |
| `icon` | varchar，nullable | 图标（预留）。 |
| `parent_id` | bigint unsigned，nullable，FK → `categories.id` | 父分类；为空即一级分类。 |
| `sort` | int unsigned | 排序。 |

主要关系：自关联父子；1:N `shops`。存在子分类或商户时禁止删除。

### 1.3 `regions`

用途：城市下行政区（如黄浦区），商户列表区域筛选项。

| 字段 | 类型/约束 | 功能说明 |
| --- | --- | --- |
| `id` | bigint unsigned，PK | 区域主键。 |
| `city_id` | bigint unsigned，FK → `cities.id`（级联删除） | 所属城市。 |
| `name` | varchar(50) | 区县名。 |
| `sort` | int unsigned | 排序。 |

## 2. 商户

### 2.1 `shops`

用途：核心实体，一家本地生活商户。

| 字段 | 类型/约束 | 功能说明 |
| --- | --- | --- |
| `id` | bigint unsigned，PK | 商户主键；详情 URL `/shop/{id}`。 |
| `city_id` / `category_id` | bigint unsigned，FK | 归属城市与分类；`(city_id, category_id)` 复合索引。 |
| `region_id` | bigint unsigned，nullable，FK | 所在区域。 |
| `owner_id` | bigint unsigned，nullable，FK → `users.id` | 店主（商户中心权限边界，null 为平台自营）。 |
| `name` / `slug` | varchar | 名称与唯一 slug（入驻时生成：名称 slug + 6 位随机串）。 |
| `cover` | varchar，nullable | 封面图（预留）。 |
| `address` | text | 详细地址。 |
| `longitude` / `latitude` | decimal(10,6)，nullable | 经纬度（地图模块预留）。 |
| `phone` | varchar(30)，nullable | 电话。 |
| `avg_price` | decimal(8,2)，nullable | 人均消费。 |
| `rating` | decimal(2,1) unsigned，默认 0 | 综合评分（点评增删后重算）。 |
| `rating_count` | unsigned int | 点评总数（与评分同步重算）。 |
| `description` | text，nullable | 介绍。 |
| `business_hours` | varchar，nullable | 营业时间。 |
| `tags` | json，nullable | 标签数组。 |
| `view_count` | unsigned int | 浏览量（详情页访问 +1）。 |
| `status` | tinyint，默认 1 | 1 营业 / 2 待审核（入驻默认）/ 0 下架；`scopeActive` 只取 1。 |

### 2.2 `shop_images`

用途：商户相册（表已建，上传界面待接入对象存储后启用）。

| 字段 | 类型/约束 | 功能说明 |
| --- | --- | --- |
| `shop_id` | FK → `shops.id`（级联删除） | 所属商户。 |
| `path` | varchar | 图片存储路径。 |
| `caption` | varchar，nullable | 说明文字。 |
| `sort` | unsigned int | 相册内排序。 |

## 3. 点评互动

### 3.1 `reviews`

用途：用户对商户的消费点评。`(shop_id, user_id)` 唯一索引保证一人一店一评（重复提交走 updateOrCreate 更新）。

| 字段 | 类型/约束 | 功能说明 |
| --- | --- | --- |
| `shop_id` / `user_id` | FK（级联删除），联合 UK | 点评归属。 |
| `rating` | decimal(2,1) unsigned | 1-5 星；详情页按 good(≥4)/mid(=3)/bad(≤2) 筛选。 |
| `content` | text | 点评正文（10-2000 字校验）。 |
| `cost` | decimal(8,2)，nullable | 本次人均消费。 |
| `images` | json，nullable | 配图（预留）。 |
| `like_count` / `reply_count` | unsigned int | 冗余计数，点赞/回复时同步增减。 |

评分重算规则：发布或删除点评后按 `COUNT(*) + AVG(rating)` 回写 `shops.rating_count / rating`（ReviewController 与 AdminController 双入口均执行；聚合查询必须绕开带排序的 reviews 关联，否则 MySQL 1140 报错）。

### 3.2 `review_replies` 与 `review_likes`

`review_replies`：`review_id`、`user_id`（FK）、`content`；商户回复以"【商家回复】"前缀写入同一表。`review_likes`：`(review_id, user_id)` 唯一，保证一人一赞，toggle 增减 `reviews.like_count`。

## 4. 收藏

`favorites`：`(user_id, shop_id)` 唯一，toggle 切换；对应动作 `POST /shop/{id}/fav`。模型必须保留 `$fillable = ['user_id', 'shop_id']`（缺失会触发批量赋值异常，已修复过一次）。

## 5. 团购与订单

### 5.1 `deals`

| 字段 | 类型/约束 | 功能说明 |
| --- | --- | --- |
| `shop_id` | FK → `shops.id`（级联删除） | 所属商户。 |
| `title` / `description` / `cover` | varchar/text | 团购内容。 |
| `original_price` / `price` | decimal(10,2) | 原价与团购价；应用层校验 `price ≤ original_price`。 |
| `stock` / `sold_count` | unsigned int | 库存与销量（支付成功按购买数量累加）。 |
| `starts_at` / `ends_at` | timestamp，nullable | 有效期（结束时间不得早于开始时间）。 |
| `status` | tinyint，默认 1 | 1 上架 / 0 下架；`scopeActive` 只取 1。 |

### 5.2 `deal_orders`

| 字段 | 类型/约束 | 功能说明 |
| --- | --- | --- |
| `order_no` | varchar(32)，UK | 订单号：`R + YmdHis + 6 位随机`。 |
| `user_id` / `deal_id` | FK（级联删除） | 买家与团购。 |
| `quantity` | unsigned int | 数量（1-99 校验）。 |
| `total_amount` | decimal(10,2) | `price × quantity`。 |
| `verify_code` | varchar(12)，nullable，支付时生成 | 核销凭证；商户中心凭码核销。 |
| `status` | tinyint，默认 0 | 0 待支付 / 1 已支付 / 2 已使用 / 3 已退款 / 4 已取消。 |
| `paid_at` / `used_at` | timestamp，nullable | 支付与核销时间。 |

越权保护：订单详情与支付入口校验 `user_id === Auth::id()`（非本人 403）；商户核销查询限定 `deal.shop_id` 为当前店主店铺。

## 6. 用户、反馈与资讯

### 6.1 `users`（Laravel 框架表基础上扩展）

| 扩展字段 | 类型/约束 | 功能说明 |
| --- | --- | --- |
| `avatar` | varchar，nullable | 头像：本地上传（`storage/app/public/avatars`，经 `/storage/` 软链访问）或 URL。 |
| `bio` | varchar(200)，nullable | 个性签名。 |
| `is_admin` | boolean，默认 false | 管理后台通行证，`admin` 中间件校验。 |

### 6.2 `feedbacks`

客服中心"意见反馈"。**表名必须显式声明** `protected $table = 'feedbacks'`（feedback 单复数同形，Laravel 复数推断会得到 `feedback`，已修复过一次）。

| 字段 | 类型/约束 | 功能说明 |
| --- | --- | --- |
| `user_id` | nullable，FK | 提交用户；游客为 null，此时 `contact` 必填。 |
| `name` / `contact` | varchar，nullable | 称呼与联系方式（登录用户默认带昵称/邮箱）。 |
| `type` | varchar(20)，默认 suggest | suggest 建议 / complaint 投诉 / bug 问题 / other 其他。 |
| `title` / `content` | varchar/text | 标题与正文（内容至少 5 字）。 |
| `status` | tinyint，默认 0 | 0 待处理 / 1 已处理（后台处理界面待建）。 |
| `reply` | text，nullable | 客服回复（预留）。 |

### 6.3 `news`

资讯栏目。`category ∈ {news 平台动态, media 媒体报道, guide 消费指南}`；`is_published` 控制可见性（详情页对未发布记录 404）；访问累加 `view_count`；`source` 仅媒体报道类使用，列表页与详情页均展示。
